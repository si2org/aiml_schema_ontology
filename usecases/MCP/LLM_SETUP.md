# Configuring the Si2 AI/ML EDA Ontology MCP Server

The Silicon Integration Initiative (Si2) EDA Ontology helps AI coding assistants to work better with the data generated by EDA tools.  You can ask your AI tool to read this ontology directly, but it can quickly burn through valuable tokens to absorb it all.  To reduce token usage, this simple Model Context Protocol (MCP) server can allow most AI tools to use the ontology on projects without using so many tokens.

If you would like to configure a server on your own personal computer, you may follow the commands given here.  These commands work on any Linux machine (including Windows Subsystem for Linux/WSL) running a BASH shell.  They may work very similarly on macOS machines with a ZSH shell, though I have not tested them.  

## Step 1 - Clone the Ontology Repository

You can do this with the command

```bash
git clone https://github.com/si2org/aiml_schema_ontology.git
```

The total required storage is about 54 MB.  The ontology is stored in the file `aiml_schema_ontology/ontology/eda_ontology.ttl`, and the MCP server is in the file `aiml_schema_ontology/usecases/MCP/server.py`.  In order to run this MCP server with OpenAI's Codex or Anthropic's Claude, you will need to have a version of Python installed that can execute versions of the `rdflib` and `mcp` packages needed by the server script.  We usually set these Python environments up with some kind of virtual environment manager.  There are many such managers to choose from.  One of the lightest-weight managers is the "micromamba" tool, but there are alternatives, including "virtualenv" and "miniconda". 

## Step 2 - Install the Virtual Environment Manager

Here we install "micromamba".  In Linux, you can do this with the command

```bash
"${SHELL}" <(curl -L micro.mamba.pm)
```

If you accept all of the default suggestions, then this command will install micromamba in `~/.local/bin` also add 12 lines to your `~/.bashrc` file.  After setup completes, you will need to start a new login shell before you will be able to execute the "micromamba" command.

## Step 3 - Create the Virtual Environment

This repository assumes that you call your virtual environment `work`.  That name is rather ambiguous when setting up an environment for a semi-permanent MCP server, so I call my environment `edamcp`.  This repository also assumes that you are using Python version 3.10.  Older versions will not work with this MCP server, but newer versions will.  If you want to use the same setup as I do, then you would create your environment with the command 

```bash
micromamba create -n edamcp python=3.10
```

Once this command completes, you can activate the environment with the command

```bash
micromamba activate edamcp
```

The prompt changes (with the newly added prefix `(edamcp)`) to indicate that the virtual environment is activated.  Now you can add the two necessary packages with 

```bash
pip install rdflib mcp==1.27.2
```

The older version of the Python `mcp` package is necessary, because the `server.py` code expects this older version.  Once the installation completes, you can test your environment by changing to the `aiml_schema_ontology/usecases/MCP` directory and using the command

```bash
python server.py --file ../../ontology/eda_ontology.ttl
```

If the environment is configured properly, you should see a number of log messages printed, including the final message `Triplestore initialized successfully`.  Press <kbd>CTRL</kbd>-<kbd>D</kbd> to close the server, and you should see the message `Shutting down triplestore connection`.  If you see these messages, then your environment is set up correctly.  When you are done testing, you can exit the virtual environment with the command

```bash
micromamba deactivate
```

## Step 4 - Configure the MCP Server for your AI Coding Assistant

To configure your MCP server, first make note of the absolute path to your Git repository.  I refer to this path below as `/path/to/your/aiml_schema_ontology`.  If you have set up your environment like mine, then you can use the prefix `micromamba run -n edamcp` to load the `edamcp` environment before running Python.  Then you need to include the full paths to the `server.py` and `eda_ontology.ttl` files.  The command would look like

```bash
micromamba run -n edamcp python server.py --file ../../ontology/eda_ontology.ttl
```

If you are using OpenAI's Codex, then edit the file `~/.codex/config.toml` and insert a new MCP server with all of the arguments needed to launch it.  I call my server "eda_ontology", and your entry would look like the following:

```
[mcp_servers.eda_ontology]
command = "micromamba"
args = [
  "run", "-n", "edamcp", "python",
  "/path/to/your/aiml_schema_ontology/usecases/MCP/server.py",
  "--file", "/path/to/your/aiml_schema_ontology/ontology/eda_ontology.ttl",
]
startup_timeout_sec = 20
tool_timeout_sec = 60
enabled = true
```

If you are using Anthropic's Claude, then you would add the server commands with the claude executable itself with something like the following command:

```bash
claude mcp add --scope user eda_ontology -- micromamba run -n edamcp python /path/to/your/aiml_schema_ontology/usecases/MCP/server.py --file /path/to/your/aiml_schema_ontology/ontology/eda_ontology.ttl
```

After running this command, you should see a new "eda_ontology" entry under the top level "mcpServers" entry in `~/.claude.json`.  

Once property configured, you should be able to use the command "/mcp" in either codex or claude and see the "eda_ontology" server listed.

## Step 5 - Use the Ontology

The AI tools will not use this MCP server unless you tell them to.  To do this, I put the following instructions near the top of `AGENTS.md` (for codex) or `CLAUDE.md` (for claude).

```
This is an EDA-related software project. It uses the EDA ontology MCP
server as a semantic reference for naming, data modeling, parser
outputs, schemas, APIs, reports, and documentation.
```

And you are off and running!  Please let us know how it works for you.
